## Ce que ça change
- **Réglages → « Les commentaires de l'analyse », comme la maquette T474** (la première partie n'avait pas repris sa mise en page : c'est rattrapé) : l'en-tête « N catégories · objets au hub, chacune avec son id · valables pour toutes tes dictées », **« ↗ Correspondances »** et **« 🤖 Prompt IA — catégories (JSON) »** ; à gauche la liste (les catégories de cette dictée, avec leur nombre ; les autres repliées ; « IA » pour celles venues de l'IA) ; à droite le commentaire, **son aperçu sur une vraie erreur de la dictée**, « Enregistrer » (au hub, pour toutes les dictées) et « Texte d'origine » ; « Ajouter une paire d'homophones ».
- **Le Prompt IA** (`mjpcPromptComposer`, présentation brève) : **la taxonomie réelle lue au hub** (domaines, familles, notions avec leurs ids et libellés prof), **les compétences lues au hub** (les termes D1.x de la table d'alias de l'app — aucune liste en dur), les types de motif connus, **les catégories existantes** (id, famille, compétence, motifs, commentaire), **toutes les erreurs de toutes les dictées** (forme → mot · type · catégorie ou NON RECONNUE, les non reconnues d'abord, les comptes) et le format JSON attendu (`categories` avec `alias: {cibles, relation}`, `homophones`) ; « 📋 Copier le prompt ».
- **« ✓ Vérifier »** (rien n'est écrit) : chaque catégorie est **testée sur ses exemples par le moteur** ; refusés, avec la raison : id absent, déjà pris ou en double, famille inconnue, **compétence absente** de la taxonomie, **motif inconnu**, exemple non reconnu ; pour le rattachement : **cible inconnue**, « egal » à plusieurs cibles, relation inconnue, **partition cassée** (une famille ou une notion aurait deux propriétaires fins dans la table, règle du 21/07) ; « Injecter » reste grisé tant qu'il n'y a rien de valide.
- **« ⬇ Injecter »** : `mjpcInjecterAvecArchive` (**l'état d'avant de `site/analyses` en corbeille, abandon si l'archive échoue**), les catégories (origine « ia », actives) et les paires ; **les rattachements proposés ajoutés à `/taxonomie/alias/tables/correction_dictee` en statut « propose »** (rien n'entre dans un décompte tant que Paul n'a pas validé) ; puis **les erreurs déjà corrigées sont reclassées** (corbeille d'abord, `reclassement-categories_…`, compté) ; le message dit tout, compté.
- **⚠ La première injection touchera beaucoup de copies** : les erreurs corrigées avant L15.1b-1 n'ont pas encore de catégorie enregistrée — Injecter la leur donne (corbeille d'abord) ; le nombre affiché sera grand (538 sur le kit du banc).
- **« ↗ Correspondances »** : le Panneau prof (`MJPC_URL?panneau=taxonomie&onglet=correspondances&app=correction_dictee`), dans un nouvel onglet ; **l'onglet « Correspondances » lui-même est L15.1b-2** (le site) — d'ici là, ce lien n'y arrive pas encore.
- **[BRANCHEMENT PROFIL — M15] L'événement du profil, branché** : chaque erreur corrigée émet vers **`/profil/<clé élève>/events/<horodatage>`** `{eleve_id, app: "correction_dictee", instance_id, nom_lisible, type: "erreur", categorie, notion_ids, notions_proposees, notions_etat, detail: {mot_fautif, mot_correct, type_dictee}, contexte: {idx}, timestamp, modifieLe}` ; **une erreur = un événement** (sa clé est gardée sur l'erreur et retrouvée par sa place : la correction suivante le met à jour, jamais un doublon ; une erreur retirée est marquée `retire`) ; **le hub n'enregistre pas une liste vide** : `notions_etat` dit en clair « aucun_rattachement » / « propose » / « valide » (jamais silencieux, avertissement du 01/08).
- **Le manifeste** : `MJPC_MANIFESTE.noeuds` + `site/analyses`, `profil` ; `MJPC_MANIFESTE.notions` = les notions des rattachements validés des catégories (lues au hub au démarrage) ; **la purge préserve** `site/analyses` et `profil`.
